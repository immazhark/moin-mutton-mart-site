# Owner console operating guide

The static /admin/ shell is public and marked noindex; Firestore membership and Rules enforce access. This build defaults to disconnected. Never add Admin SDK credentials to the browser, repository or Cloudflare build variables. Configure the five PUBLIC_FIREBASE_* names from .env.example only for an approved environment. The production project is refused on every host except the canonical apex; preview projects must be separate and use an exact approved preview host.

Session-scoped Google sign-in uses the browser popup. A popup-blocked browser is instructed to open the full browser and retry; mobile redirect is not implemented until the authorized auth-domain flow can be tested. Actual Google login and a real owner's phone trial remain launch gates.

After signing in, an active member sees the server-fetched catalogue. Edit rates in decimal rupees, choose availability, listing status, visibility and stock; blank stock means unknown, zero means none. The shop default can hide saved rates without deleting them. Public rates in the document are not confidential. The UI refuses publication until charging metadata is approved in source; provisional values are not invented.

Save performs the verified transaction, not a client-only write. Failed/uncertain saves retain the exact intent in memory and, when available, a bounded same-tab session recovery record. Verify/retry reuses its original operation ID. A conflict preserves the draft and requires reload and review. A successful transaction may be followed by a failed refresh; the UI pauses editing until verified data is reloaded. Never use an offline queue. Ordinary unsaved drafts are memory-only; a reload or sign-out may lose them. Interrupted submitted saves can be recovered in the same tab for two hours, subject to browser storage and membership verification. Explicit sign-out clears recovery; the beforeunload warning is best effort.

Export validated draft JSON privately on the device. Import accepts only the bounded exact versioned format, restores into the local draft and requires the normal audited save; no UID, revision, timestamp or operation ID is restored. Backups may contain rates and stock; keep them private. Do not upload them to the website repository.

Production membership bootstrap and catalogue seed are separately approved trusted-console operations. Never deploy these Rules or seed live values without explicit approval.

## Phase 2 — isolated authentication and owner security

Separate Firebase app names (`moin-public` and `moin-owner`) keep the owner session out of public catalogue reads. The one-time change from the old app name can require a fresh sign-in; it does not change membership or data. Production uses the exact approved HTTPS apex and production project; independent preview projects must use their own Firebase-hosted auth handler, not an unrelated project or arbitrary auth host. Loopback HTTP is allowed solely for local development; emulator harnesses additionally require the demo project and fixed loopback ports. Do not use a custom production authDomain unless its auth handler has been independently verified. Sign-out locks edit/save actions while it is in progress. No production Google login has been attempted.

For the owner account, enable Google 2-step verification and recovery options, use a private browser/device, sign out on shared devices, and never share passwords or recovery codes. Grant active membership only through a trusted console after verifying the UID; promptly revoke membership if account access is lost or suspicious activity is detected. IAM membership and Google sign-in alone do not grant shop editing. Review the audit revision/actor/snapshot through a trusted admin process, retain encrypted private backups outside Git, and do not perform a blind restore after an uncertain save. Export before intentionally discarding a conflict/draft. Exact same-tab recovery is now implemented; see below.

## Phase 6 — daily work and interrupted saves

1. Sign in, verify membership, search or select a product category. Use Changed only to review edited items. Filters are view-only, not a bulk action. Rates and availability and manual stock are visible directly; the rate-display override remains in details. All changes publish together; no local optimistic success.
2. If a save is interrupted, keep the tab open or reload that same tab. After verified membership and current catalogue load, Verify / retry uses the original immutable draft and operation ID. Nothing is automatically submitted. A previously committed result is acknowledged without another revision. A conflict preserves the draft; export before reloading and reviewing against the latest revision. Do not use an expired or unavailable recovery record to infer success or failure; verify the prior audit through the administrator before another save. The same operation may be retried from memory even when recovery storage is unavailable.
3. Session recovery contains only validated catalogue draft, project ID, administrator UID, revision, operation ID and original creation time. It expires for restoration after two hours (not extended on retry). It is not encrypted or an authorization boundary. Storage deletion is best effort, including on verified completion, denied membership or explicit sign-out. Browser restart/session restore and tab cloning vary; don't rely on this as a durable backup. If shared device or loss of access, sign out and clear site data. No passwords, email addresses, tokens, customer notes or full account profile in this application record. Ordinary unsaved drafts are not persisted.
4. Export a private backup to a trusted device, and load to review. An import is a draft, not publication; save still checks membership, revision and transaction audit. Never upload private backups to Git. Actual Google login, owner's device, recovery after a real production interruption and approved charging units remain launch gates.
